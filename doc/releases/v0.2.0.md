PAIA 0.2.0: the command the whole pack-algorithm family shares, a
zpaq-std plugin, and two fixes for Windows. Compression is unchanged:
0.2.0 writes the same `.paia` bytes as 0.1.0 (checked on the 43 test
samples), and every file 0.1.0 wrote opens.

```sh
paia a anims\*.gif               # -> anims\*.paia, each checked before it is kept
paia x -o out\ anims\*.paia      # the originals, byte for byte
paia list anims\*.paia           # what each holds
```

## The family's command

The same commands, options and exit codes as PJA and its siblings
(`doc/CLI.md`, in each archive):

- **Commands**: `a`, `x`, `list`, `t`, `info` (a file's structure, without
  compressing it), `report` (what to attach to an issue, with its link),
  `bench`, `selftest` (samples inside the binary, on each path), and
  `--version`.
- **Options**: `-o`, `--output-dir`, `-f`, `-th`, `--max-output`,
  `--keep-corrupt`, `--no-verify`, `--no-sync`, `--clean-temps`, `-n`, `-q`,
  `--stats`, `--json`, `--cpu=pascal|c`.
- **Exit codes**: 0 done, 1 a file failed, 2 usage, 3 a bug of PAIA's own
  (the file is stored as it is, and `paia report` says what to send).
- **Durable writes**: a temporary file, flushed to the disk, renamed
  without replacing anything, and the folder flushed. Ctrl-C, `kill` or a
  closed terminal leave no file under an output's name.
- **Threads**: one file a thread, the largest first.
- **Windows**: `paia` expands `*` and `?` itself; names are read in UTF-16,
  so any name works; what it prints shows every character on a console,
  and is UTF-8 in a file or a pipe (`--json`, `report`).

Measured against the other two tools that recompress GIF (precomp 0.4.8,
paq8px v217), on 5 GIFs:

| | PAIA | precomp | paq8px |
|---|---|---|---|
| 1,000 single-bit flips in the compressed file: a wrong GIF given back without an error | **0** | 198 | 960 |
| the same flips: a wrong GIF left under the output's name | **0** | 971 | 996 |
| killed while writing: a file under the output's name | **no** | yes (empty) | yes (empty) |

## In zpaq-std (experimental)

`pas/plugin/build.sh` builds PAIA as a [zpaq-std](https://github.com/YadeWira/zpaq-std)
plugin (`codecs/paia.so`, `paia.dll` or `paia.dylib`), with one codec a
format: `paiagif1`, `paiaflc1`, `paiaani1`, `paiaanim1`, `paiawebp1`.

```sh
zpaq-std a backup.zpaq folder\ -m5 -sat:paia:paiagif1:paiaflc1:paiaani1:paiaanim1:paiawebp1
```

On a folder of 229 files (124 animated among 105 others, 111.8 MB):
`-m5` 62.79%, `-m5` with PAIA **43.42%**, in less time.

- **`-sat` only**: there is no ZPAQL decoder yet, so these blocks open
  only with the plugin.
- **`+rcmd` (zpaq-std 2.9.0)**: a file of these formats that PAIA does
  not take (a truncated one, say) goes with the method each codec
  recommends: `-m1` for GIF and WebP, whose data are compressed already,
  and `-m5` for FLI/FLC, ANI and IFF ANIM. zpaq-std 2.7.2 and 2.8.0 write
  the same archive as before. How it was measured: `doc/PLUGIN.md`.

## Fixed

- **32-bit builds and a chunk of nearly 4 GB**: the ANI, IFF ANIM, WebP
  and FLI readers held a chunk's size in a 32-bit integer, where such a
  size wrapped negative, and read before their buffer. On Windows x86 an
  ANI of the sample corpus made 0.1.0 stop with an access violation; the
  file was stored as it is, with exit 3, as for any bug of its own.
  64-bit builds were not affected. `tests/hugesize` holds one such file
  of each format.
- **What `paia` prints on Windows**: names outside the console's code page
  were printed as `?`, and output to a file was in that code page instead
  of UTF-8. The files and their names were always right.

## Platforms and checks

Linux (x86-64, arm64, x86), macOS (Apple silicon), Windows (x64, x86).
CI checks every commit on all six, three builds each, and that the
`.paia` files are the same bytes everywhere. This release was also run
on a real Windows 10 (x64 and x86) and Windows XP SP3 (x86): `selftest`,
every sample through `a`, `t` and `x`, wildcards, names outside ASCII
(ñ and ü on both, Japanese on Windows 10), and the exit codes.

**Compatibility**: every `.paia` a release writes opens in every later
release (`doc/STABILITY.md`). The test suite extracts files the 0.1.0
release wrote, on every platform.
