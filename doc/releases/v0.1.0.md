The first release of PAIA (packAnimatedImage Algorithm): lossless
recompression of animated images, in FreePascal with the GIF pixel
model's core in C; no libraries. A **proof of concept**.

```sh
paia a anim.gif          # -> anim.paia
paia x anim.paia         # -> anim.gif, the same file byte for byte
```

**Formats**: GIF (any LZW encoder), FLI/FLC (8 bits), ANI (bitmap
frames), IFF ANIM (BODY and Byte Vertical Delta frames), WebP (VP8, VP8L
and lossless alpha, still or animated). Anything else in a file goes
through as bytes, and every file comes back the same.

On the sample corpus and sets made from it (each file compressed,
extracted and compared):

| | files | PAIA 0.1.0 | xz -9e |
|---|---|---|---|
| GIF | 62 | **42.07%** | 95.60% |
| GIF, optimized (ffmpeg, ImageMagick) | 8 | **52.13%** | 98.15% |
| FLI/FLC | 29 | **31.07%** | 46.45% |
| ANI | 26 | **8.16%** | 14.69% |
| IFF ANIM | 14 | **45.08%** | 52.22% |
| WebP, animated | 11 | **77.23%** | 88.99% |

**Nothing is written unless it verified**: `a` decompresses its own
result and compares it with the input first; `x` checks the size and the
BLAKE3-128 hash the `.paia` carries.

**Platforms**: Linux (x86-64, arm64, x86), macOS (Apple silicon), Windows
(x64, x86). CI checks every commit on all of them, three builds each,
and that the `.paia` files are the same bytes everywhere.

**Compatibility**: as in the whole family, the formats freeze at 1.0.0.
A `.paia` made by 0.1.0 may not open in a later 0.x version (it is
refused as an unknown version, not misread).

The command's manual is `doc/CLI.md` (in each archive); how it works, and
every measurement, are in the
[wiki](https://github.com/YadeWira/PAIA/wiki) and
[doc/CODEC.md](https://github.com/YadeWira/PAIA/blob/main/doc/CODEC.md).
